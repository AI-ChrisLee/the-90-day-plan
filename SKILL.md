# The 4-Week Plan

The offer is confirmed, the script is written, the deck is built. What is left is how to spread,
and that question dies by arithmetic, not by a menu. Your work, in one line: **ask hours a day
once, read the lane off the founder's own files, and write `squad/90-day-plan.md`, one page: a
header and 4 rows, every row the same cycle, sized to those hours.** The founder's part is one
number, one yes, the hour of the block, and one line every Sunday.

**The cycle is 3 beats, and only 3.** Run what already wins. Measure the results. Improve what
won.

| Beat | When | What it is |
|---|---|---|
| Run | Monday to Saturday. The making usually Monday and Tuesday, the send or publish from Wednesday | The squad copies what already wins and makes it the founder's; the same week the founder's hand puts it in front of strangers on their own account. An asset that did not go out the week it was made did not happen |
| Measure | Sunday, about 10 minutes | 2 numbers per lane, read off the founder's own files, and only off things that have finished. A number that has not finished is held, never guessed |
| Improve | Sunday, right after Measure | One line, in exactly 2 forms: one named change, or `holding until <number>, week N`. It is Monday's brief. Most weeks read holding, and that is the plan working |

The hour is not a beat. One hour a day, by hand, on people: partners, customers, the people who
gave the founder something. It sits on the calendar (g1) and on the plan's header as one line, a
habit with no count. Measure reads the system, never the hour. Sunday has no block: the hour, the
read, the line, the post.

This skill runs in ANY founder's repo. Read `.claude/squad-roots.md` first, the instance file
every member-run skill shares; its values win over the `squad/` paths below, which are worked
examples, and a row reading "(none yet)" is an unanswered field rather than an override. Legacy
repos carry `.claude/spine-roots.md`: read that as the fallback. Three rows are this skill's own:
`hours a day`, written at beat 1; `daily lane` (OUTREACH, CONTENT or ADS), written at the yes;
`plan doc`, the Google Doc's link, written when one is made. `founder name` is read for the Doc's
title. `ads gate` is a1's row and is only read here. **Never write into the `lane` row.** That row
is the Winning Scrape's and holds a content-research path.

## The run map (where you run, where you STOP)

| Beat | Mode |
|---|---|
| 1 THE HOURS | HUMAN INPUT: one number, and nothing prints before it |
| 2 THE LANE AND THE PLAN | AUTO: the files read, the lane, the arithmetic, the plan written to the template and printed whole under the lane line |
| 3 THE YES | **STOP · GATE: the founder's yes and the block hour; a different lane word reprints.** Then AUTO: the stamp, the roots rows, and the Google Doc when a Drive connector answers |
| 4 THE SUNDAY CELL | HUMAN INPUT: "Put this in week N's Measure: ____ / Improve: ____". Then AUTO: the 2 cells written, and nothing else |
| 5 RENEW | AUTO: the 4 Measure and Improve cells, `squad/pipeline.md` and the lane's own log read. Then HUMAN INPUT: the hours again, and the lane word in the 2 cases beat 5 names. Then AUTO: plan 2 written whole under its own heading, 4 new rows. Then **STOP · GATE: the yes and the block hour**, then the stamp, the roots rows, a new Google Doc |

The beat numbers are the section numbers below. Beats 1 to 3 write the plan, the default, and they
run once per plan. Beat 4 is the one thing written between the yes and the renewal. Beat 5 is
`renew`, at week 4 or any Sunday after it, and it ends on beat 3's gate. One question, one print,
one gate, in each mode. Never pause an automated beat to ask a small question; never run through
a gate because the answer seems obvious.

**Resuming.** The rule keys on the OUTPUTS, never on what a session remembers: check them in this
order and continue at the first one missing or incomplete.

| Missing or incomplete | Resume at |
|---|---|
| `.claude/squad-roots.md` has no `hours a day` row | beat 1 |
| the row is there and `squad/90-day-plan.md` does not exist | beat 2 |
| the plan's newest block has a header line with no `confirmed <date>` stamp | the gate only, never a rewrite: beat 3's gate when the unconfirmed block is the first in the file; beat 5's gate when it is not (the plan-numbered Doc title, the rename of the previous Doc, the `hours a day` row rewritten, and only the new block rendered) |
| the newest block is confirmed, the roots file has no `plan doc` row, and a Drive connector answers | beat 3's Doc step only: the Doc, the link, the row |
| the newest block is confirmed and today is before week 4's Sunday | beat 4 on "put this in week N"; on a bare `/4weeks` or a "continue", one line: which week this is, which Measure and Improve cells are still blank, and the 2 forms the Improve cell takes; on the word `renew`, one line naming the date the renewal opens, and nothing is written |
| the newest block is confirmed and today is week 4's Sunday or past it | on a bare `/4weeks` or a "continue", say so in one line and offer `/4weeks renew`; on the word `renew`, beat 5, a new block. Never rewrite a confirmed block |

## The outputs

1. `squad/90-day-plan.md`: THE file, one page per plan, written to the exact shape in
   `references/plan-template.md`. Beat 4 writes 2 cells of it. `renew` appends a block under it
   and never edits a line above.
2. The `hours a day`, `daily lane` and `plan doc` rows in `.claude/squad-roots.md`.
3. Off disk, only when a Drive connector answers: one Google Doc, "4-week plan · <founder name>",
   the plan rendered as HTML. Created at the yes, never before it. `renew` makes a new one, its
   plan number in the title, because a Doc's body cannot be rewritten.

Nothing else gets written.

## 1 · THE HOURS

**First, a self-check.** One file inside THIS skill's folder, next to `SKILL.md`, must open:
`references/plan-template.md`. If it is missing, stop and tell the founder to finish the install:
copy the whole skill folder, `references/` included.

**Then the one question, when the roots file holds no `hours a day` row.** The resume table
already keeps this beat from firing on a finished run. Nothing prints before the question, not
the lane, not a file read, not a table:

> Hours a day for the system, beyond the hour you spend on people?

One number. Write it into `.claude/squad-roots.md` as `| hours a day | N |`. The week said back
("so N hours a day on the system, Monday to Saturday, and the hour on top?") is the first line of
the next message, never a second question; a wrong number gets corrected at the gate. A row
already there is never re-asked. The hour on people is not in the number and is never asked
about: it is a habit, and this plan does not count it.

## 2 · THE LANE AND THE PLAN

**Read, in this order, asking nothing about any of it.**

| File | What it answers |
|---|---|
| `.claude/squad-roots.md` | `hours a day`; `founder name`; `ads gate` (a1's row: open or shut) |
| `squad/business.md` | who buys: a buyer you can list by name, or one you cannot. Missing: stop on one line, g4 or g5 builds it |
| `squad/mep/*/plan.md` | the deck, built for whom |
| `squad/clients/*/notes.md` | who asked for a named thing; THE NEXT STEP with a date |
| `squad/pipeline.md` | who almost paid; money received |
| `squad/ads-money-card.md` | ADS only: the daily number the founder chose (a2), and the lead ceiling the Measure column reads against. Missing: the daily number is the `ads gate` row's monthly divided by 30, and the working is shown |

**The lane is read, never asked.** ADS reads first when both its halves are there; otherwise the
first 2 rows decide.

| The files say | The lane | Chris's level rule |
|---|---|---|
| the buyer in `business.md` can be listed by name (an owner, a realtor, a clinic, a job title in a city), and there is something to show: the deck in `squad/mep/`, or a client folder with a dated next step | OUTREACH | proof in hand, outreach |
| the buyer cannot be listed by name (a consumer, a creator, a broad audience), or there is nothing to show yet | CONTENT | nothing yet, content |
| money received in `pipeline.md` on the offer as it stands, and the `ads gate` row reads open | ADS | money and the gate, ads |

No hours threshold decides the lane, and nothing opens or closes on one: content at 1 hour a day
is a lane sized in minutes. A founder who dreads the lane the files picked says the other word at
the gate, and their word is written with the same care.

**The count is one line of arithmetic.** The hours are the system's, whole; nothing comes off
them first.

| Lane | The arithmetic |
|---|---|
| all | minutes a day for the system = hours a day x 60 |
| OUTREACH | by hand a day = minutes / 3, rounded down to a 5, capped at 50 (the cap said out loud when it bites: the inbox is the limit, not the hours). A week, Wednesday to Saturday, = a day x 4, and that is what carries the week's touches by the founder's hand until the routine sends (o4). The list is 50 rows; when a day x 4 is under 150, the week's list is 25 rows and the plan says so |
| CONTENT | the minutes, and 1 recording a week: recorded Tuesday, published Wednesday, the same slot every week |
| ADS | the daily number off `squad/ads-money-card.md` (a2), all 7 days, x 7 for the week, behind a1's gate. No card yet: the `ads gate` row's monthly / 30 is the daily, x 7 the week, and both lines show their working. Neither on disk: the spend row reads `your daily number (a1, a2)` and no figure is printed. The minutes go on the creative, then on the read and the leads |

The plan carries this arithmetic as a small table, never as a code block: the founder reads the
plan in a Google Doc and a black box does not read there. Never print a weekly number the send
days do not produce.

**What goes in each column.** The template holds the exact words per lane.

| Column | What it holds |
|---|---|
| Week | the number and its dates, Monday to Sunday |
| Run | written now, per lane, off the template's worked cells: the asset made that week AND the send or publish that puts it in front of strangers. OUTREACH: the week's list (50 rows, or 25 when `by hand a day x 4` is under 150), one trade, one town, one broken thing per row, and the 3 touches (o1, o2), the list entering Wednesday, the touches out by the founder's hand; the out-counts come off the list rather than being copied (week 1 the list x 2, weeks 2 and 3 the list x 3, week 4 the list x 2), and week 4 is the deck for the one name worth an hour (g7). CONTENT: 1 video, the winner in the founder's topic copied, packaged, scripted, cut (c1 to c4), published Wednesday, and the post every night (g3). ADS: 1 concept cut 3 ways, built paused (a2, a3), live in a NEW ad set at the daily number on the founder's go, untouched once it starts. No cell names a day except the send or publish trigger. No daily task column exists |
| Measure | blank when the plan is written. Sunday's 2 numbers, off finished things only: OUTREACH delivered and replies (o3); CONTENT 7-day views and asks (c6); ADS cost per lead and leads (a4). Week 1's Sunday reads sent and delivered counts and little else |
| Improve | blank when the plan is written. Sunday's one line, in exactly 2 forms: one named change, or `holding until <number>, week N`. Killing a dead ad and answering people are hygiene, not the change. A change is the brief for Monday's Run, never an edit to what is running |

OUTREACH has 2 shapes, because a warm domain and a new domain cannot run the same plan 1. The
plan is written for a warm domain; `new domain` said at the gate reprints the 4 Run cells with the
ramp (25 rows in weeks 1 and 2, touch 1 at 10, 15, 20 and 25 a day) and the line that this plan
reads deliverability only, with no reply read before plan 2.

**Then write `squad/90-day-plan.md` whole**, to `references/plan-template.md`, in its order, and
print ONE message:

- line 1: the hours said back
- the lane, one line; why, one line off the files; "say a different word for a different lane"
- the whole plan, as written

Every number in it is the founder's hours, the arithmetic, or a count a file holds. Never a
projected result.

## 3 · THE YES

**STOP.** Ask for 2 things and nothing more: the yes, and the hour of the block (the plan
proposes 9:00 for the hours a day, Monday to Saturday; the founder confirms or names another). A
different lane word reprints the lane line, the arithmetic table and the 4 rows for that lane,
written with the same care; `new domain` reprints the 4 Run cells. A changed hour reprints the
block line only. On the yes: stamp the header line `confirmed <today's date>`, the only record
this gate happened and what the resume check reads, and write `| daily lane | <lane> |` into
`.claude/squad-roots.md`.

**Then the Google Doc, AUTO.** Look for a Drive connector: a tool whose name ends in `create_file`
on a server whose name is a UUID prefix. Detect by that suffix and that shape, never by a server's
own name or description. When one answers:

1. Render the block being confirmed, and only that block, as HTML with real tags, to the
   document law: `<h1>4-week plan · <founder name></h1>`, the header line in a `<p>`, an `<h2>`
   per section (The cycle, The plan, The arithmetic, The weeks), one `<p>` per line, the 3-word
   line in `<b>`, the header fields and the arithmetic as `<table>` elements, the miss clause in
   a `<p>`, and the 4 weeks as one `<table>` with a header row of the 4 columns. No markdown in
   it, no code block.
2. Call `create_file` with `title` "4-week plan · <founder name>" (the roots file's `founder
   name` row; missing, the founder's first name from the chat, and nothing invented), `textContent`
   the HTML, `contentMimeType` `text/html`. The connector converts it to a Google Doc with the
   headings and the tables intact.
3. Print the link, one line, and say what it is: the plan as it stands on the day of the yes.
   Every Sunday line lands in the plan on disk, and the renewal makes a fresh Doc. Write
   `| plan doc | <link> |` into `.claude/squad-roots.md`.

No connector: one line, "connect Google Drive (g2) and I put it in Docs next time", and carry on.
Never a second line about it, never a retry. Sharing stays as Google made it; the founder flips
it if they want it seen.

Then one line back: `/bip` writes the day; Sunday is the read (o3, c6 or a4), then "put this in
week N" with the 2 numbers and the one line, then `/bip sunday`, which closes on that line; week
4 is `/4weeks renew`.

## 4 · THE SUNDAY CELL

The one thing written between the yes and the renewal. The founder says, on a Sunday or after
it:

> Put this in week N's Measure: ____ / Improve: ____

Also "put this in week N" with the 2 parts in any order. Without an N, the week is the row whose
Sunday is today, or the last row that has ended. Then AUTO:

- The Measure cell takes what the founder said: the 2 numbers, or a number and `held until
  <when>` where the thing has not finished. Nothing is computed, nothing is looked up.
- The Improve cell takes exactly 2 forms: one named change, or `holding until <number>, week N`.
  A line in neither form is not written; one line names the 2 forms, and the run waits for the
  line. Never a second question.
- Write the 2 cells of that row in `squad/90-day-plan.md`, on disk, and print the row back.
  Nothing else in the file moves. The Google Doc is a copy to read, not the copy that is read
  back; it is not touched.

A missed Sunday is written, never made up: a row whose Sunday has passed with both cells blank
stays blank until the founder puts a line in it, and the renewal reads the blank as a week nobody
read.

## 5 · RENEW

Week 4's Sunday, or any Sunday after it. A plan is renewed, never extended; 3 plans make the 90
days. **Read first**, asking nothing, and only these:

- the newest block's 4 rows: the Measure and Improve cells. Four lines that say what the founder
  read and what they changed or held; a blank cell is a week nobody read, and it is said as that.
- `squad/pipeline.md`: replies by bucket, the next touch, what went out last, money received.
  This is where money is counted, and nowhere else.
- the lane's own log, whichever exists. `squad/outreach-read.md` (o3: the batches, sent and
  replied) and `squad/ads-log.md` (a4: one row per week) hold the lane's numbers, so read every
  row. `squad/content-log.md` holds only what shipped and when (date, title, link, video id) and
  holds no numbers; count its rows for videos published. A lane whose log does not exist prints
  `(no log on disk)` and runs on the pipeline and the 4 rows alone.

**Then one message, the only ask in this mode:**

- the hours again: "Hours a day for the system for the next 4 weeks, beyond the hour you spend on
  people?"
- the lane read again off the files as in beat 2, printed with its one line why, in exactly 2
  cases: the 4 weeks made no money, or `squad/pipeline.md` shows money received and the `ads gate`
  row reads open, which is the row that selects ADS. The founder says the word either way. Money
  with a shut gate keeps the lane and changes only how it is run; the founder is not asked.

**Then write plan 2 whole**, under `## PLAN 2 of 3 · <today's date>` (PLAN 3 of 3 next; after
plan 3 the count starts again at plan 1 of 3 of the next 90, and the heading carries a running
number too, `## PLAN 4 · plan 1 of 3 · <date>`, so no 2 headings match). In the template's
order: the header line with the new hours and lane and `confirmed (not yet)`, the header table,
the arithmetic recomputed, the miss clause, and 4 new rows dated on from the renew date, numbered
1 to 4 again under their own heading. Week 1's Run carries the last written Improve line as its
brief: a named change becomes what week 1 makes and puts out; a hold keeps the Run as the lane
ran it. Measure and Improve are blank again. Never edit a line above the new heading. Print the
block whole.

**STOP.** The same gate as beat 3: the yes and the block hour. On the yes, stamp the new header
line `confirmed <date>`, rewrite the `hours a day` and `daily lane` rows in the roots file where
they changed, and make the Google Doc as at beat 3 with the new block rendered, titled "4-week
plan · <founder name> · plan 2" (its plan number, whichever it is); the `plan doc` row is
rewritten to the new link. When the connector carries a title update, rename the previous Doc
"4-week plan · <founder name> · plan 1 (done)" before printing the new link; when it does not,
print one line naming the old Doc as done. No connector, the same one line, carry on.

## Rules

- Every message is scannable: a short header, then bullets or a table. The founder is deciding,
  not studying.
- Never send a message, publish a piece, post anywhere, load a sequence, start an ad set, book a
  slot or spend a budget on their behalf, and never wire anything that would. The Google Doc is
  the one thing made off disk, and it is a copy of the plan.
- Never price past `squad/business.md`. Nothing here touches a price.
- Never invent a number, a name or a need. Every number printed is one the founder said, a file
  holds, or the arithmetic produced from the hours they said.
- Never sum a post. Money is read off `squad/pipeline.md`; the lane's numbers off its own log and
  the founder's Sunday line; `squad/posts/` is never opened for numbers.
- Never a menu. One lane, one print, and the founder's word.
- Never a fenced block in the plan file. The arithmetic is a table there; the plan is read in a
  Doc.
- Never a daily task column, a day count, a 13th row, or a cell that names a day for anything but
  the send or publish trigger.
- The day is `/bip`'s, the Sunday read is the lane's (o3, c6, a4), and `/bip sunday` closes on
  the Improve line. This skill writes the 2 Sunday cells on the founder's line and nothing else
  before the renewal.
